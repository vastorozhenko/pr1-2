# Модель загроз (STRIDE)

## Контекст
Публічний Flask вебдодаток, SQLite, мінімальна аутентифікація.

**Активи:**

| Актив | Цінність |
|---|---|
| Облікові дані користувачів (таблиця `users`) | захоплення облікових записів |
| Сесійний cookie | вхід від імені користувача |
| `SECRET_KEY` | підпис сесій: хто знає ключ, може підробити будь-яку сесію |
| Вміст БД (таблиця `posts`) | цілісність і конфіденційність даних |
| Сервер застосунку | виконання коду, доступність сервісу |

**Потоки даних і межі довіри:**

```
 [Браузер / атакувальник]
          │ HTTP :5000  (межа довіри 1: Інтернет -> застосунок)
          ▼
 [Flask app: /, /echo, /search, /login, /profile] ── SECRET_KEY з ENV
          │ SQL  (межа довіри 2: застосунок -> файл БД)
          ▼
 [SQLite demo.sqlite3: users, posts]
```

Усі параметри запитів (`msg`, `q`, `username`, `password`) і сесійний cookie надходять з-за межі довіри 1 і вважаються недовіреними.

## STRIDE-матриця

| Категорія | Загроза | Компонент | Вимога |
|---|---|---|---|
| **S**poofing | підбір пароля без обмеження спроб; підробка сесії, якщо відомий `SECRET_KEY`; крадіжка cookie через XSS | `/login`, сесія | AUTH-2, CONF-1, SESS-1 |
| **T**ampering | зміна даних через SQLi; clickjacking | `/search`, усі сторінки | INP-1, HDR-1 |
| **R**epudiation | вхід і невдалі спроби не журналюються, атаку неможливо розслідувати | `/login` | LOG-1 |
| **I**nformation Disclosure | читання таблиці `users` (паролі відкритим текстом) через SQLi; показ виконаного SQL на сторінці; XSS для крадіжки cookie | `/search`, `/echo`, БД | INP-1, OUT-1, STOR-1 |
| **D**enial of Service | масові запити до `/search` з важкими шаблонами LIKE; масовий підбір паролів | `/search`, `/login` | AUTH-2, NFR-5 |
| **E**levation of Privilege | віддалене виконання коду через відладчик Werkzeug (`debug=True`); доступ до чужого профілю через підроблену сесію | конфігурація | CONF-1, AUTH-1 |

## Сценарії атак

**1) SQL Injection у /search** (R1)
- Вектор: параметр `q` вставляється в SQL через f-string. Запит `/search?q=' UNION SELECT id, username, password FROM users--` виводить логіни й паролі замість публікацій.
- Виявлення: SAST (Bandit B608, Semgrep), мануальна перевірка запитом з `'`; у журналі вебсервера запити з `'`, `UNION`, `--` у параметрі `q`.
- Пом'якшення: параметризовані запити (INP-1), прибрати показ виконаного SQL.

**2) Reflected XSS у /echo** (R2)
- Вектор: параметр `msg` повертається як HTML без екранування. Посилання `/echo?msg=<script>...</script>`, надіслане жертві, виконує скрипт у її браузері.
- Виявлення: Semgrep (власне правило), DAST (ZAP), мануальна перевірка: тег `<script>` повертається у відповіді без змін.
- Пом'якшення: вивід через шаблон Jinja2 з автоекрануванням (OUT-1), CSP (HDR-1).

**3) Слабка автентифікація /login** (R3)
- Вектор: немає обмеження спроб, тому пароль можна підібрати перебором; паролі в БД відкритим текстом, тому разом з R1 атакувальник отримує всі паролі.
- Виявлення: Semgrep (власне правило про порівняння пароля відкритим текстом); журнал входів (LOG-1): серія невдалих спроб для одного логіна.
- Пом'якшення: PBKDF2-хеші (STOR-1), блокування після 5 спроб (AUTH-2), журналювання (LOG-1).

**4) Підробка сесії та виконання коду через небезпечну конфігурацію** (R5)
- Вектор: якщо `SECRET_KEY` не задано, використовується відоме значення з коду, і атакувальник може підписати cookie з будь-яким `user_id`. Запуск `python src/app.py` вмикає `debug=True` на `0.0.0.0`: відладчик Werkzeug дозволяє виконати код на сервері.
- Виявлення: Bandit B201 і B104, Semgrep (власні правила).
- Пом'якшення: `SECRET_KEY` лише з ENV без запасного значення, debug вимкнено (CONF-1).

**5) Вразливі залежності** (R4)
- Вектор: використання бібліотеки з відомою CVE.
- Виявлення: pip-audit у CI.
- Пом'якшення: оновлення залежностей за результатами pip-audit.
